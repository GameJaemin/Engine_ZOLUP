2026-11-25 기준. 엔진과 렌더러 소스를 수정하지 않고 `Game` 계층에 게임 규칙과 실행 상태를 구현한다. 첫 목표는 협동 보행, 소리, 심박, 추격, 숨기, 재시작을 한 공간에서 검증하는 플레이 가능한 구간이다.

코드 존재와 실제 게임 동작 검증은 구분한다. 이번에는 소스를 읽어 연결 가능성을 확인했으며 빌드와 실행 검증은 하지 않았다.

### 먼저 해결할 제약

1. **마침표 입력**: `Engine/Source/Input/Key.h`에 `.`가 없다. `InputState`만으로 정식 협동 조작을 구성할 수 없다. 개발용 S/D 모드로 먼저 검증한다. 정식 모드는 게임 측 입력 어댑터에서 기존 ImGui Win32 입력 경로의 `ImGuiKey_Period` 수신을 검증하는 방안을 우선 조사한다. 이 경로를 쓰면 두 발 모두 같은 입력 경로에서 수집해 순서와 반복 제거 기준을 통일한다. 최소화, 포커스 복귀, 같은 프레임 두 입력, 짧은 탭 누락을 검증하기 전에는 지원 완료로 보지 않는다. 실패 시 게임 전용 Win32 어댑터 가능성을 검토하며 키 변경은 기획 합의가 필요하다.
2. **실시간 후방 CCTV**: `Engine::RunFrameLoop`가 `GetRenderRequest()` 하나를 소비하고 공용 그리기 목록을 초기화한다. 렌더 타깃이 있다는 사실만으로 메인 뷰와 후방 뷰의 동시 렌더링을 보장할 수 없다. 현재 공개 앱 경로에서는 원안 지원이 확인되지 않았다. 임의로 렌더러를 직접 호출하지 않는다. 별도 실험에서 공개 기능으로 가능한지 확인하고, 불가능하면 엔진 변경 금지 조건 아래 원안은 충족 불가 항목으로 남긴다. 거리 표시 등 대체 UI는 기획 변경안이며 CCTV 완료로 취급하지 않는다.
3. **사운드 재생**: 조사한 게임과 엔진 소스에서 공용 오디오 서비스를 찾지 못했다. 청각 판정은 게임 데이터만으로 구현하고, 실제 SFX는 게임 전용 오디오 어댑터와 라이브러리 연결을 별도 작업으로 둔다. 재생 실패가 AI 판정을 바꾸면 안 된다.
4. **전등 수**: 포인트 라이트는 현재 첫 활성 4개만 제출한다. 작은 검증 맵은 이 범위에 맞춘다. 전체 맵은 논리 전등과 제한된 실제 라이트를 분리하는 배정 방안을 시험한다. 많은 전등의 동시 조명과 기존 베이크 조명의 동적 소등은 보장할 수 없다.
5. **소리 링**: 셰이더나 데칼 추가를 전제하지 않는다. 기존 메시와 재질로 링을 표현할 수 있는지 시험한다. HUD 투영 링은 깊이 가림과 바닥 밀착이 다른 대체안이다.

## 콘텐츠 구조

```text
GameApplication

    RhythmController                 발 입력과 모멘텀
    InteractionSystem                대상 선택과 행동 가능 검사
    HearingSystem / HeartSystem      청각 자극과 심박

    Navigation / CollisionQueries    경로와 실제 이동 가능성
    CheckpointService                전체 게임 상태 저장과 복원
    Presentation                     포즈, 카메라, HUD, 전등, 오디오
  World                              엔진이 제공하는 장면 객체 소유
```

게임 상태를 원본으로 두고 장면 객체는 그 결과를 표시한다. HUD, 애니메이션, 오디오 콜백이 직접 AI나 플레이어 상태를 바꾸지 않는다. 일반 이벤트 버스를 먼저 만들지 않고, 세션 내부의 명시적인 명령과 프레임 이벤트 목록으로 시작한다.

`World`는 `GameObject`를 소유한다. 세션은 런타임 `ObjectID`와 콘텐츠의 영구 ID를 연결하고 객체 포인터를 저장 파일에 넣지 않는다. 세션과 어댑터는 `World`보다 먼저 정리한다.

## 플레이어 상태와 입력

기획 4.11의 7개 주요 상태를 그대로 기준으로 삼는다.

| 상태 | 진입 | 종료와 핵심 규칙 |
| --- | --- | --- |
| Locomotion | 시작, 특수 행동 종료 | 박자 이동과 상호작용 허용 |
| Fallen | 평지에서 같은 발 연속 | 실수 소리 1회, 일어나기 완료 후 이동 |
| Hidden | 테이블 상호작용 | 잡기 제외, 카메라 회전 허용, 출구 검사 후 이동 |
| Hanging | 봉 상호작용 | 잡기 제외, 10초 소진 시 낙하와 실수 소리 |
| Ladder | R 또는 T로 사다리 잡기 | 발 입력마다 42cm, 실수 시 90cm 미끄러짐 |
| Crawling | R 또는 T로 통로 진입 | 통로 경로로 이동, 끝에서 이동 복귀 |
| Caught | 같은 층에서 노출 상태로 130cm 이내 | 짧은 연출 후 체크포인트 복원 |

진입, 유지, 이탈 애니메이션은 각 상태의 하위 단계로 둔다. 특수 상태 사이에는 직접 전이하지 않는다. Caught는 사다리에서도 가능하지만 Hidden과 Hanging은 제외한다. 통로는 몬스터 진입을 막는 연결 구조로 안전성을 보장하고, 통로 전체에 무조건 무적 플래그를 주지 않는다.

협동 모드는 S=왼발, .=오른발, R=왼손, T=오른손, 마우스=시야, Esc=일시정지다. 개발용 솔로 모드는 S/D, 좌우 클릭, 마우스다. 운영 모드를 데이터로 구분하고, 현재 ThirdPerson의 F/R/T 디버그 조작과 동시에 처리하지 않는다.

### 박자 이동 제안

키를 누르고 있는 상태가 아닌 누름 이벤트를 처리한다. 마지막 발, 입력 간격, 콤보, 모멘텀을 저장한다. 자동 반복은 걸음으로 세지 않는다.

- 반대 발을 0.75초 이내에 누르면 콤보 유지, 같은 발이면 상태에 따른 실수다.
- 0.75초를 넘기면 콤보가 끊긴다. 긴 대기 후 첫 발도 이전 발 때문에 넘어져야 하는지는 미정이므로 제안 기본값은 마지막 발을 초기화하는 것이다.
- 빠른 입력 기준 0.17초, 이상적 가속 시간 3.3초, 최고 속도 680cm/s를 외부 데이터로 둔다. 품질 점수를 모멘텀에 누적하고 입력이 끊기면 감쇠한다. 정확한 곡선과 `MomentumDecay=0.9`의 차원은 플레이 테스트로 정한다.
- 평지에서는 모멘텀 기반 연속 이동을 우선 제안한다. `StepDistance`를 동시에 독립 이동량으로 더하면 이중 가속되므로 사용하지 않는다. 한 발 고정 거리 모델을 원하면 모멘텀 모델과 함께 재정의한다. 사다리의 42cm는 별도 이산 이동이다.
- 같은 프레임 양발은 원래 수신 순서를 유지한다. 수신 순서가 없는 입력 어댑터에서는 동시 입력 정책을 정해야 하며 임의로 두 번의 완벽한 박자로 인정하지 않는다.
- 마우스 yaw로 진행 방향을 정한다. 사다리 내려가기와 통로는 데이터 경로 방향을 사용한다.

실수, 숨기 진입, 잡힘 등 이동을 중단하는 전이에서 남은 걸음 명령을 폐기한다. 정지와 일시정지를 구분해 일시정지 중 심박과 AI 타이머도 멈춘다.

## 소리와 심박

### 청각 판정과 오디오 재생 분리

`SoundStimulus`는 sourceID, 종류, 위치, floorID, 반경, 발생 순번, 종료 시각, 우선순위, AI 반응, CrossFloor, IgnoreRadius를 가진다. 지속 발소리와 심장 소리는 프레임마다 갱신하고, 넘어짐과 사물 소리는 1회 이벤트 또는 지정 수명으로 관리한다.

기본 판정은 같은 층이며 XZ 거리 제곱이 반경 제곱 이하다. 벽 차폐 검사는 하지 않는다. `CrossFloor`는 층 제한만, `IgnoreRadius`는 거리 제한만 해제한다. 사물의 AI 반응이 Ignore면 선택 후보에서 제외한다. 포효 SFX를 AI 청각 자극으로 되먹임하지 않는다.

정렬 제안은 플레이어 자극 그룹 > 사물 그룹, 그룹 내 Priority 내림차순 > 발생 순번 내림차순 > 영구 ID 순서다. 플레이어 우선 규칙을 사물의 높은 Priority가 뒤집지 못하게 한다. Priority와 최신 소리의 정확한 관계는 기획 확인 항목이다.

```text
footRadius = speed > 0이고 발소리 허용 상태이면
             50 + (408 - 50) * clamp(speed / 680, 0, 1)^p
             그 외 0
heartRadius = BPM >= 100이면
              50 + (1500 - 50) * clamp((BPM - 100) / 50, 0, 1)^p
              그 외 0
p 기본값 = 2
표시 링 반경 = max(footRadius, heartRadius)
```

테이블과 봉은 발소리만 없애며 심장 소리는 남는다. 사다리와 통로도 실제 이동 속도에 따른 작은 소리를 낸다. 실수 소리는 4500cm이며 1000cm 이내 추격, 그 밖 의심이다. 숨기 이탈 시 50cm 자극은 1회만 생성한다.

층은 단순히 캐릭터 Y를 640으로 나누지 않는다. 각 방의 바닥 영역과 계단·사다리 연결에 명시한 층 경계를 사용한다. 지하 음수 좌표, 봉 높이, 계단 중간에서 같은 층 판정이 흔들리지 않게 한다. 정확한 층 전환 위치는 레벨 데이터로 정한다.

### 심박 갱신 우선순위 제안

1. 잡힘이나 복원 단계면 해당 진행 정책을 적용한다.
2. 추격 중이면 숨었어도 150을 유지한다. 새 추격 진입도 즉시 150이다.
3. 숨은 상태이며 의심이면 진정 타이머로 100 미만까지 낮춘다.
4. 숨은 상태이며 정찰이면 초당 4 하강한다.
5. 노출 상태에서 10m 이내면 공포 상승을 적용하고 정지 하강은 금지한다.
6. 이동 중에는 `72 + 48 * speed/680` 목표를 향해 상승하며 하강하지 않는다. 최고 속도 유지 규칙을 추가 적용한다.
7. 노출, 정지, 10m 밖이면 초당 2.5 하강한다.

동시에 적용 가능한 공포 상승과 이동 상승의 합산 여부는 기획 확인이 필요하다. 제안은 가장 큰 상승량을 적용해 중복 급등을 피하는 것이다. 최고 속도 유지의 3초 대기 후 상승인지, 3초 동안 120에서 150으로 상승인지도 본문 표현을 정리해야 한다.

**수식 경계 문제**: `(150-100)/2=25`로 정확히 2초 내리면 100이므로 “2초 뒤 100 미만”과 다르다. 제안은 진정 완료 시 임계값 바로 아래로 명시적으로 넘기는 정책이다. 100에서 조용해지는 것으로 바꾸면 `100 이상 들림` 규칙을 위반한다.

## 스티치 상태와 길찾기

상위 상태는 Patrol, Chase, Suspicious다. Listening, LookAround, Roaring, Smashing은 행동 하위 단계로 둔다. 상태별 포효 종료 목적을 기록해 테이블 파괴 후에는 Chase, 추격 포기 후에는 Patrol로 간다.

| 사건 | 처리 |
| --- | --- |
| 노출 플레이어의 들리는 발소리 또는 심장 소리 | Chase, 400cm/s |
| 멀리서 들린 실수 소리 | Suspicious, 600cm/s, 같은 층 5m 이내 400cm/s |
| 노출 플레이어의 지속 소리 둘 다 끊김 | 마지막 청각 위치에서 의심 행동, 두리번, 포효, 정찰 |
| 추격 중 테이블이나 봉으로 숨음 | 마지막 청각 위치 접근, 같은 층 수평 3m 안 연속 2초 후 의심 |
| 의심 중 숨어 있는 플레이어 심장 소리 | 주변에 머물며 진정을 기다림, 추격 재진입 금지 |
| 숨은 플레이어 심박이 100 미만 | 정찰 복귀 |
| 소진된 테이블에서 추격 숨기 판정 충족 | 파괴 1.4초, 안전 이탈, 포효 2초, 추격 |
| 추격 중 통로 진입 | 포효 후 정찰 |
| 추격 중 사다리로 층 변경 | 포효 후 정찰, 계단으로 플레이어 층 이동 |

3m 밖으로 나가면 숨기 관찰 타이머를 초기화한다. 도달 불가능한 숨기 위치의 마지막 접근점 도착 후 SearchTimeout은 3초다. 통로 진입의 명시적 추격 포기를 일반 도달 불가 처리보다 우선한다.

**위치 정보 분리**: 청각 추격 목적지는 들은 위치만 갱신한다. 기획이 명시적으로 허용한 플레이어 층 따라가기와 5m 감속, 잡기, 전등 연출은 별도 질의다. 소리를 못 들을 때 실제 플레이어 좌표를 매 프레임 추격 목적지로 쓰면 청각 게임이 성립하지 않는다.

길찾기는 게임 전용 웨이포인트 그래프와 A*로 시작한다. 노드는 층·방·문·계단 연결을 표현한다. 스티치 경로에 사다리와 통로 간선을 넣지 않고 계단만 허용한다. 각 간선은 반지름 60cm, 높이 296cm의 통과 공간이 검증되어야 한다. 경로 위를 실제 충돌 질의로 이동하며 경로선 자체를 충돌 해결로 취급하지 않는다.

이 방식은 초기 검증 맵을 위한 제안이다. 맵 규모와 경로 품질이 요구하면 게임 전용 Recast/Detour 연동을 후속 선택지로 둔다. NavMesh를 엔진 기능으로 먼저 만들지는 않는다.

## 상호작용과 동적 충돌

후보는 거리, 행동 가능한 상태, 화면 중앙과의 각도, 장애물 검사로 고른다. 가장 가까운 물건만 고르면 기획의 시선 선택을 어긴다. 숨기 이탈 방향은 카메라 yaw의 수평 전방이다.

테이블 이탈 후보는 카메라 전방, 진입 위치, 몬스터 반대편 순서로 검사한다. 바닥과 플레이어 캡슐 전체의 여유를 검사하고 1.1초 이탈 경로도 검사한다. 셋 다 막히면 임의 텔레포트하지 않는다. 제안 정책은 안전 상태 유지와 배치 오류 표시이며, 강제 파괴 이탈도 안전 출구가 하나 이상 있어야 하도록 맵 검증에 포함한다.

### 테이블 수명

첫 추격 숨기에서 `remainingUses=1`을 0으로 만들되, 그 숨기 세션에는 파괴가 허용되지 않는다. 진입 전 수명이 이미 0이었는지를 `canBreakThisOccupancy`로 기록한다. 현재 수명만 검사하면 첫 사용부터 깨지는 버그가 생긴다.

파괴 중에는 자발 이탈과 잡기를 막는다. 파괴 완료 시 숨기 기능과 충돌 프록시를 제거하고 온전한 모델을 잔해 모델로 바꾼다. 잔해는 화면에 남지만 양쪽 캐릭터 이동을 막지 않는다.

### 충돌 데이터 구분

`ThirdPersonScene`은 정적 메시의 월드 삼각형을 복사하므로 움직이는 문과 파괴 테이블을 그대로 포함하면 원래 위치에 충돌이 남는다. 게임 측 `GameplayScene`에서 정적 건축물과 동적 프록시를 분리한다. 문·테이블·잔해는 정적 삼각형 수집에서 제외하며, 문은 회전 또는 상태 기반 박스, 테이블은 숨기 슬롯과 파괴 가능한 프록시로 처리한다. 초기 소형 맵은 이벤트 시 재구성도 가능하지만 전체 맵을 매 프레임 다시 만들지 않는다.

### 사다리와 통로

사다리에는 상하 앵커와 끝점, 층 경계, 내려가기 카메라를 둔다. 실수 횟수는 같은 사다리 점유 중 누적하고 이탈 시 초기화한다. 다섯 번째부터 4500cm 실수 소리다. 미끄러짐은 하단 범위로 제한하며 별도 무한 추락은 만들지 않는다.

통로는 진입점·출구점·경로·카메라를 가진다. 사다리 내려가기와 통로에서 마우스 회전을 무시하고 0.5초 동안 카메라를 섞는다. 진입 중 입력 잠금과 이탈 후 복귀를 상태 단계에서 처리한다.

### 손과 아이템

손마다 최대 하나를 보유한다. 아이템 상태는 World / Held(owner, hand) / Consumed로 둔다. 스티치 아이템 운반은 보류하고 일반 소유 표현만 남긴다. 아이템을 든 채 특수 행동할 때 내려놓기와 자동 드롭 중 어느 정책인지는 확정하지 않는다. 첫 검증 구간에는 아이템이 필요 없다.

## 애니메이션과 표현

콘텐츠 애니메이터가 클립 시간, 블렌드, 상태 완료를 소유한다. 기본 로컬 포즈는 별도 보관하고, 엔진 자동 클립 재생과 게임 포즈 쓰기를 동시에 하지 않는다. 최종 포즈는 기존 `SetRestPose`와 필요한 노드의 `SetTransform`으로 전달한다. 이는 API 이름상 의미가 맞지 않는 우회이므로 어댑터 한 곳으로 제한한다.

플레이어는 저속 한 발 Walk_L/R과 연속 이동용 클립 세 개를 구분한다. 연속 이동에서는 정규화된 발 위상을 맞춰 보간한다. 기획 8.1의 Walk/Jog/Run과 엑셀의 Walk/Run/Sprint 이름이 다르므로 실제 클립명은 `AnimationBindings.json`에서 역할에 연결한다. 300/480은 상태 선택 기준이며 세 클립의 기준 속도 배치는 테스트로 확정한다.

스티치는 Patrol_Walk와 Run 사이만 짧게 크로스페이드한다. 촉수는 지정한 뼈와 자손 마스크에만 절대 로컬 포즈를 보간하는 방식부터 시작한다. 가산 애니메이션으로 가정하지 않는다. 몸 갈라짐에 필요한 뼈를 마스크에 포함하고, 이동 루트와 다리 트랙이 촉수 클립에 덮이지 않게 한다. 촉수와 잡기 판정은 독립이다.

엑셀에서 확정인 애니메이션을 제작 우선 목록으로 사용하되, 보류 클립 때문에 확정 게임 기능까지 자동 보류하지 않는다. 봉은 기능이 필요하지만 Grab/Idle/Struggle 클립은 보류이므로 초기에는 임시 포즈로 검증한다. Wake_Up 복원 연출은 저장된 캐릭터 상태를 덮어쓰지 않는 표시 단계로 취급한다.

HUD는 심박 숫자와 심전도, 상호작용 키, 매달리기 게이지만 우선 구현한다. 100 기준선과 목표 문구는 표시하지 않는다. 시작·Esc 안내에서는 P1 핑크, P2 시안, 공통 초록을 사용한다. 진단 수치는 개발 HUD로 분리한다.

## 데이터와 맵 연결

기존 맵 포맷을 바꾸지 않고 시각 맵과 게임 메타데이터 파일을 함께 로드한다. 현재 `LoadLevel`의 로컬 계층 ID를 곧바로 전역 저장 ID로 가정하지 않는다. 게임 파일에 안정적인 `entityID`와 시각 객체 바인딩 경로를 두고 초기화 때 런타임 ID로 해석한다. 이름 중복과 바인딩 누락은 시작 오류로 보고한다.

| 파일 | 내용 |
| --- | --- |
| Gameplay.json | 이동, 심박, 소리 곡선, 스티치 속도, 타이머, 카메라 튜닝 |
| AnimationBindings.json | 역할별 클립명, 기준 속도, 마스크 뼈, 행동 완료 시각 |
| ObjectSounds.json | 기획 4.7의 사물 종류와 사건별 소리 데이터 |
| Map.gameplay.json | 영구 ID, 층 영역, 숨기 슬롯, 동적 충돌, 문, 경로, 카메라, 체크포인트 |

모든 파일에 버전을 둔다. cm, 초, 도를 사용하고 NaN, 음수 반경, 0 이하 분모, 중복 ID, 끊어진 경로, 누락 클립을 로드 단계에서 검증한다. 사물 종류 ID와 배치 인스턴스 ID는 구분하며 쿨다운은 인스턴스와 사건 조합으로 관리한다. 기획 엑셀은 제작 목록으로 보존하고 첫 구현에서 런타임 xlsx 파서를 추가하지 않는다.

## 프레임 처리 계약 제안

고정 60Hz 게임 시뮬레이션과 프레임별 표현을 분리한다. 엔진의 `OnUpdate`에서 누산하며 발 누름 이벤트는 첫 해당 틱에서 한 번만 소비한다. 타이머는 실제 경과 시간 대신 같은 시뮬레이션 시계를 쓴다. 프레임 지연 시 누산량과 틱 상한 정책을 명시해 무한 따라잡기를 피한다.

1. 입력 명령과 일시정지, 복원 요청을 수집한다.
2. 이전 확정 AI 상태를 기준으로 플레이어 행동 전이를 결정하고 이동한다.
3. 이동과 이전 AI 상태로 심박을 갱신한다.
4. 소리 자극을 만들고 AI 청각과 상태를 갱신한다. 추격 진입의 심박 150은 이 시점에 즉시 반영한다.
5. 스티치를 이동하고 잡기, 숨기 관찰, 파괴 결과를 판정한다. 관찰 타이머는 틱당 한 번만 진행한다.
6. 진입·이탈 효과를 한 번 적용하고 충돌·진행 상태를 확정한다. 심박과 청각을 재귀적으로 재실행하지 않는다.
7. 확정된 틱 끝에서 체크포인트를 캡처한다.

프레임 표현 단계에서는 `World::Tick` 이후 최종 변환, 게임 포즈, 카메라를 한 번 적용하고 삭제 예정 객체를 정리한다. `OnGui`는 표시와 UI 명령 큐 작성만 맡는다. 최소화로 GUI 프레임이 없는 경우 오래된 입력을 재사용하지 않는다.

## 체크포인트

좌표만 되돌리면 테이블, 아이템, AI가 저장 시점과 달라진다. 저장은 콘텐츠 전체 스냅샷으로 설계한다.

- 맵 ID, 저장 버전, 콘텐츠 데이터 버전.
- 플레이어 위치·방향·상태·모멘텀·발 순서·심박·스태미나·점유 상호작용과 타이머.
- 스티치 위치·상태·행동 단계·목적지·마지막 청각 위치·순찰 번호·타이머·촉수 상태.
- 테이블 수명·파괴·점유 세션, 문 상태, 열쇠 소유와 위치, 퍼즐·진행 플래그, 잔해.
- 진행 중인 지속 자극, 쿨다운, 재현에 필요한 난수 상태.

기본 정책은 안정된 틱 경계에서 저장하는 것이다. 진행 이벤트가 특수 행동 중에도 저장을 허용한다면 상태 단계와 클립 진행 시간까지 추가한다. 시작 스냅샷도 만들어 첫 체크포인트 전 잡힘을 처리한다.

복원은 입력 잠금, 임시 자극과 예약 명령 폐기, 장면 객체 재생성 또는 상태 재적용, 영구 ID 재연결, 충돌과 경로 재구성, 포즈·카메라 동기화 순서로 한다. 실패 시 부분 복원 상태로 플레이하지 않는다. 기존 저장은 임시 파일 쓰기 성공 후 교체하는 방식으로 보호한다. 실제 저장 위치는 소스/콘텐츠 폴더와 분리한다.

## 구현 순서와 완료 조건

| 단계 | 구현 범위 | 완료 조건 |
| --- | --- | --- |
| 0 | 게임 앱 연결, 입력·포즈·GUI 제약 실험 | S/D 동작, 정식 마침표 입력 가능 여부 판정, CCTV 지원 여부 기록 |
| 1 | 한 방, 박자 보행, 넘어짐, 카메라, 심박, 소리 | 이상적 입력 약 3.3초에 680 도달, 반복키 무시, 같은 발 실수 1회 |
| 2 | 스티치 1마리, 청각, 그래프 이동, 테이블 | 들림→추격→숨기→의심→정찰 루프와 두 번째 추격 숨기 파괴 재현 |
| 3 | 죽음과 체크포인트 | 테이블·잔해·AI·심박이 저장 시점으로 복구 |
| 4 | 봉, 사다리, 통로, 층 연결 | 10초 낙하, 다섯 번째 사다리 실수, 계단 추종, 통로 추격 포기 |
| 5 | 열쇠·문·진행 이벤트·전등·실제 오디오 | 문 상태와 길찾기 일치, 플레이어가 청각 정보를 실제 소리로 인지 |
| 6 | 확정 퍼즐, 전체 맵, 엘리베이터, 연출 보완 | 확정된 챕터 완료 조건과 최종 저장 복원 검증 |

첫 작업 단위는 단계 0~2의 작은 테스트룸이다. 완성 맵과 모든 애니메이션을 기다리지 않고 대체 모델로 규칙부터 검증한다. 이것은 전체 게임 완료 범위를 줄이는 결정이 아니라 구현 순서다.

필수 시나리오는 BPM 99.9/100/150, 거리 130/300/1000/4500cm의 경계, 다른 층의 같은 XZ 위치, 숨기 2초 중 반경 이탈, 최초 테이블 사용과 재사용, 파괴 도중 잡기 금지, 막힌 이탈, 사다리 위 잡힘, 저장 전후 잔해 충돌, 포커스 복귀 시 유령 발 입력이다. 규칙 테스트는 장면 없이 명령과 시간을 주입할 수 있게 하고, 카메라·포즈·오디오·입력 지연은 실제 플레이로 확인한다.
