# 자산 경로 규칙

## 파일 열기

- 엔진과 게임의 자산 경로는 저장소 루트 기준 UTF-8 상대 경로로 작성합니다. 경로 구분자는 `/`를 사용합니다. 파일과 폴더 이름에는 대문자와 소문자를 섞어 쓸 수 있습니다.
- 자산을 읽을 때는 경로의 대소문자를 구분하지 않습니다. 요청 경로, glTF의 `uri` 표기가 디스크의 실제 이름과 대소문자만 달라도 같은 파일을 읽습니다. 다만 새로 작성하는 경로는 디스크의 표기와 맞춥니다.
- 현재 엔진은 Windows 전용이며, 파일을 열 때의 대소문자 무시는 Windows 파일 시스템의 기본 동작에 의존합니다. 대소문자 구분을 켠 폴더나 다른 운영체제에서는 보장하지 않습니다.
- `Paths::GetAbsolutePath()`로 파일을 열 경로를 구합니다. 파일을 열 때는 요청 경로의 대소문자를 바꾸지 않고 그대로 운영체제에 넘깁니다.
- `Paths::GetRootDirectory()`는 실행 파일에서 네 단계 위의 폴더 이름을 `Binaries`와 대소문자 구분 없이 비교합니다. 출력 폴더의 위치는 [빌드 설정](../BuildSetup.md#도구-집합-선택과-출력-경로)을 따릅니다.

## 캐시와 렌더러 조회

- `Paths::MakeAssetKey()`는 디스크를 조회하지 않고 `.`과 `..`을 정리하고, 구분자를 `/`로 통일하며, ASCII `A-Z`를 소문자로 바꿉니다. 그 외 UTF-8 문자는 보존합니다.
- 모델과 텍스처 캐시는 절대 경로에서 키를 만듭니다. 텍스처는 같은 파일이라도 sRGB와 UNorm 형식을 서로 다른 캐시 항목으로 둡니다.
- Hakko 리소스 이름은 경로가 아니라 에셋 객체의 실행 중 번호(`Asset::GetInstanceID()`)로 만듭니다. 경로는 파일 위치와 캐시 키에만 씁니다.
- `Checker.png`와 `checker.png`처럼 ASCII 대소문자만 다른 이름은 같은 키로 비교하므로, 같은 폴더에 서로 다른 자산으로 두지 않습니다.
- 캐시에 이미 있는 자산은 파일을 다시 열지 않고 처음 만든 객체를 돌려줍니다. 따라서 자산 객체에 저장된 경로와 이름은 처음 성공한 요청의 표기이며, 디스크의 실제 표기와 다를 수 있습니다.
- 자산 경로를 비교하거나 경로로 자산을 찾는 코드는 문자열을 그대로 비교하지 않고 `Paths::MakeAssetKey()`로 만든 키를 비교합니다.

## 경로 기록

- 레벨이나 에셋 데이터처럼 자산 경로를 파일에 기록하는 기능은 디스크의 실제 표기를 기록합니다. 자산 객체에 저장된 경로는 요청한 표기일 수 있으므로 그대로 기록하지 않습니다.

## 실패 로그

- 경로를 구하거나 파일을 읽는 데 실패하면 요청한 경로 또는 실제로 열려고 한 경로와 실패 이유를 오류 로그에 남깁니다.
- PNG 디코더 생성 실패 로그에는 실제로 열려고 한 경로와 WIC가 반환한 `HRESULT`를 함께 남깁니다.
